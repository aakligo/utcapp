# ENV-001 - Development Environment Cleanup

## Ticket Information

- Project: UTC Student Services Portal
- Ticket: ENV-001
- Related Incident: INC-002
- Date: 2026-11-26
- Priority: High
- Environment: Development
- AWS Region: us-east-1
- Status: Resolved - Pending Git Review

## Objective

Prepare a clean, consistent, low-cost AWS development
environment for subsequent DevOps engineering activities.

## Problem Statement

The development environment contained obsolete Terraform
plans, diagnostic files and infrastructure drift caused
by AWS resources being removed outside Terraform.

Terraform planning also failed because a database secret
was scheduled for deletion.

## Root Cause

- Infrastructure changes outside Terraform.
- Unconditional Secrets Manager data source.
- ALB dependencies without conditional protection.
- Hardcoded infrastructure activation settings.
- Accumulation of temporary diagnostic files.

## Resolution

- Archived 105 temporary files outside the repository.
- Created and verified private Terraform state backups.
- Made database secret lookup conditional.
- Made ALB listener rules conditional.
- Added Terraform moved blocks.
- Parameterized Auto Scaling desired capacity.
- Added interface VPC endpoint feature flags.
- Added CloudWatch feature flag.
- Disabled unnecessary billable infrastructure.
- Reconciled Terraform state with AWS.

Actual AWS billing has not been independently verified.

## Known Limitations

- Application intentionally offline.
- Full application functionality has not been retested.
- Database restoration has not been tested.
- Disabled services must be reactivated when required.
- Local environment settings are excluded from Git.

## Incident Resolution

INC-002 infrastructure drift was resolved successfully.
Terraform configuration and managed AWS infrastructure
are consistent at the time of validation.

## Lessons Learned

- Avoid unmanaged infrastructure changes.
- Review Terraform plans before applying.
- Use conditional resources and feature flags.
- Back up Terraform state before infrastructure changes.
- Validate infrastructure after every deployment.
- Maintain cost-conscious development environments.
